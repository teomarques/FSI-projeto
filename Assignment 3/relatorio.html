3. Testes WSTG – Fase 1

Testes efetuados contra http://192.168.100.20:3000. Scan ZAP com política FSI-Full-Scan (Threshold: Low, Strength: High). Scan autenticado em 22/05/2026 com admin@juice-sh.op.

3.1 WSTG-INFO – Information Gathering

[WSTG-INFO] Divulgação de Tecnologias: A aplicação expõe Express 4.22.1, SQLite e Angular em cabeçalhos e mensagens de erro. Comunicação sobre HTTP simples (sem HTTPS).
[WSTG-INFO] Private IP Disclosure (1 inst.): Endereços IP internos divulgados em respostas.

3.2 WSTG-CONF – Configuration and Deployment Management

[WSTG-CONF-05] CORS Wildcard (1803+ inst.): Access-Control-Allow-Origin: * em todas as respostas — qualquer domínio pode fazer pedidos cross-origin.
[WSTG-CONF-12] CSP Wildcard / CSP Ausente: Política CSP com diretivas wildcard (6 inst.) e ausente em várias páginas. Não oferece proteção contra XSS.
[WSTG-CONF] Missing Anti-clickjacking Header (35 inst.): X-Frame-Options ausente — vulnerável a clickjacking.
[WSTG-CONF-04] Hidden File Found (4 inst., scan autenticado): Ficheiros sensíveis acessíveis detetados com acesso autenticado.

3.3 WSTG-IDNT – Identity Management

[WSTG-IDNT-01] Enumeração de Utilizadores: O painel /#/administration expõe todos os emails registados (admin@juice-sh.op, jim@juice-sh.op, bender@juice-sh.op, e outros 7) após autenticação como administrador.

[WSTG-SESS-04] Session ID in URL Rewrite (153 inst.): Token de sessão transmitido via URL — exposto em logs, histórico do browser e cabeçalho Referer.

3.7 WSTG-INPV – Input Validation

[WSTG-INPV-05] SQL Injection – Login Bypass: Payload ' OR 1=1-- no campo email autentica como administrador sem password. RDBMS: SQLite. CVSS: Crítico.
POST /rest/user/login  |  {"email":"' OR 1=1--","password":"test"}  →  200 OK (admin login)
[WSTG-INPV-01] DOM XSS (2 inst.): Uso de funções JavaScript perigosas (eval(), innerHTML) detetado.

3.8 WSTG-ERRH – Error Handling

[WSTG-ERRH-01] Application Error Disclosure (6 inst.) + Full Path Disclosure (12 inst.): Erros expõem Express 4.22.1, tipo de BD (SQLite) e caminhos internos do servidor.

3.9 WSTG-CRYP / WSTG-BUSL – Criptografia / Lógica de Negócio

Não aplicável — comunicação HTTP (sem TLS) e lógica de negócio fora do âmbito, conforme enunciado.

3.10 WSTG-CLNT – Client Side Testing

[WSTG-CLNT] Site Isolation / Feature Policy: Cabeçalhos Cross-Origin-Opener-Policy e Permissions-Policy ausentes ou deprecados (1699 inst.).

5. Conclusões

Fase 1

  • O Juice Shop apresenta 3 vulnerabilidades críticas: SQL Injection no login, password de admin trivial (admin123) e painel de administração exposto.
  • Foram identificadas 18 vulnerabilidades em 9 das 11 categorias WSTG, com ZAP (scan automático, scan autenticado, fuzzer) e testes manuais.

Fase 2

  • O WAF (Apache + ModSecurity + OWASP CRS v3.3.5) bloqueou com sucesso o SQL Injection de login bypass (403 Forbidden, SQLI anomaly score = 8). Foi necessária configuração adicional para inspeção de JSON (requestBodyProcessor=JSON).
  • O WAF não bloqueia vulnerabilidades de lógica aplicacional (passwords fracas, rotas Angular /#/, IDOR) — requerem correções na aplicação.
  • O WAF introduziu dois novos alertas: Multiple X-Frame-Options (cabeçalho duplicado, 880 inst.) e Server Version Leakage via Apache (24637 inst.) — corrigíveis com Header always unset e ServerTokens Prod.
  • O WAF é uma camada de defesa eficaz contra ataques de injeção HTTP, mas não substitui boas práticas de desenvolvimento seguro.
